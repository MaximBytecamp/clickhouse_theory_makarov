# Проверка главы В.2

Дата: 18.11.2026. Материал: `../index.html`.

## Карта содержания и границы

- Из В.1: назначение СУБД, операционная и аналитическая нагрузка. В.1 находится в отдельном worktree другого окна; повторного раздела OLTP/OLAP в В.2 нет.
- Новое: один набор заказов в табличном и документном представлении; строковая и колоночная организация; поля для карточки и отчёта; различие операций и их гарантий.
- Оставлено другим главам: установка и клиенты — модуль 0; типы, создание таблиц и развёрнутый синтаксис запросов — модуль 1; устройство частей, сортировка, индексы, сжатие и измерения — модуль 3.
- Конфигурации в тексте: PostgreSQL 17, стандартный heap без колоночных расширений; MongoDB 8.0, WiredTiger; ClickHouse 26.8.36.3, семейство MergeTree.

## Выполненные примеры

Все запросы — только SELECT, без изменения общих баз и без перезапуска сервера.

| Проверка | Результат |
|---|---|
| `SELECT version()` | `26.8.36.3` |
| `orders.sql` | 101 / Анна / Москва / 1200 / paid; 102 / Борис / Казань / 800 / new; 103 / Анна / Москва / 600 / paid |
| `one-order.sql` | 102 / Борис / Казань / 800 / new |
| `paid-sales.sql` | 1800 |
| Та же сумма без условия статуса | 2600 |
| Самостоятельная задача: у заказа 102 статус paid | 2600 |
| Ответ самопроверки: сумма paid с группировкой по city | Москва / 1800 |

Повторить примеры можно вставкой SQL-файлов в Play UI своего стенда. Функция `values` создаёт набор внутри запроса; этот опыт не проверяет физическое хранение MergeTree.

Два PNG сняты в настоящем Play UI отдельным Chromium/профилем, через Playwright. Студенческие кадры сохранены в исходном размере 1280 × 760. На втором кадре Play UI показывает одну запись вертикально. Схемы нарисованы HTML-элементами и не выдаются за кадры интерфейса.

## Вычитка A–E

- A: таблица исходных заказов, JSON-представление документа, две схемы механизма, два настоящих кадра и таблица гарантий. Во всех четырёх содержательных разделах есть наглядный блок. На телефоне строки таблицы гарантий раскладываются вертикально.
- B: последовательность «модель → хранение → операции → гарантии»; переходы после содержательных разделов. OLTP/OLAP не пересказываются. В шпаргалке — вопросы выбора, в ошибках и самопроверке — применение к ситуации.
- C: при машинном проходе после первой редакторской правки — 11,0 слова в предложении и два предложения длиннее 25 слов; окончательный проход — 172 предложения, средняя длина 10,8 слова, предложений длиннее 25 слов нет. Показатель относится к связному тексту разделов, который выделяет `review.py`, не к SQL и таблицам.
- D: убраны обороты «а не», искусственные противопоставления и оценочные усиления. Полный текст прочитан подряд, включая подписи, таблицу гарантий, ответы и источники.
- E: числа проверены запросами; названия элементов интерфейса сопоставлены с кадрами; область атомарности оговорена отдельно для каждой операции. PostgreSQL и MongoDB не запускались, сведения сверены с официальной документацией. Benchmark отсутствует.

## Инструменты и интеграция

Использованы существующие `review.py` и `snap.mjs` навыка vychitka. Первичный `review.py` не выделял разделы без заголовков вида `h2 id="sN"`; главе добавлены эти идентификаторы, смысловые якоря секций сохранены. `snap.mjs` проверил обе схемы на 1280 и 390 px.

Дополнительный локальный Playwright-прогон проверяет HTTP-загрузку страницы, изображения, якоря, уникальность id, ссылки, раскрытия, увеличение кадров, Escape и копирование SQL. Проверки выполняются в собственных процессах, с временным HTTP-сервером и отдельными браузерными контекстами. Общие браузерные окна и настройки проекта не используются.

Окончательный прогон после мобильной правки прошёл на 1280 и 390 px: ширина документа равна ширине окна как с закрытыми, так и с раскрытыми details; оба изображения загружены; 21 ссылка и уникальность якорей проверены; восемь внешних источников отвечают HTTP 200; ошибок JavaScript нет; lightbox, Escape и содержимое буфера после копирования SQL проверены. Таблица исходных заказов на узком экране прокручивается внутри своего контейнера; её широкие элементы не создают переполнение страницы. Схемы и вертикальная таблица гарантий просмотрены отдельно, неперехваченного горизонтального переполнения нет.

Область изменения ограничена этой главой и её assets. Глобальные стили, book.js, оглавление, PLAN.md и списки кадров не менялись. Ветка предназначена для отдельной интеграции: ссылку из общего оглавления и переходы между новыми вводными главами добавляет интегратор. В main не сливать автоматически.
