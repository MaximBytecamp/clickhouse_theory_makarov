# Проверки главы 1.3

Для редактора, который интегрирует ветки справочника.

## Область и карта материала

- Изменяется только `temy/13-pustoe-znachenie/index.html` и её `assets/`.
- Входные знания: строки, столбцы, основные типы, простой SELECT.
- Результат: различать 0, пустую строку, NULL, пропуск при вставке и значение по умолчанию; прослеживать влияние на вычисления и агрегаты.
- За пределами главы: устройство CREATE TABLE, пакетная загрузка, полные таблицы логики, GROUP BY, сжатие и измерение производительности.
- Убраны повторы определения NULL в нескольких вводных блоках, повторный каталог типов, отдельная таблица выбора с повторением лекции, дублирующий глоссарий и длинное сравнение с MongoDB.
- Стоимостной опыт прежней версии снят: несжатый объём, память запроса, хранение и время нельзя объединять в один показатель.

## Изолированное окружение

Проверка: 18.11.2026, образ `clickhouse/clickhouse-server:26.8.36.3`, UTC.
Собственный контейнер `ch13-null-20261118`, HTTP `127.0.0.1:18383`.
Контейнер не использует имена, порты или тома существующего стенда.
Общий ClickHouse не изменялся и не перезапускался.

Подготовка — `setup.sql`, SQL-вывод — `verified-results.json`.
В TSV `\N` означает NULL, пустое поле означает пустую строку.
В Play UI команды выполнялись отдельными запросами; в клиенте — последовательно.
Таблицы Memory и имена предназначены для отдельного опыта. Повторная вставка
добавляет дубли; автоматического сброса общего стенда в материалах нет.

## Проверенные различия

- Исходные скидки: 0, 10, NULL. Подписи: пустая строка, sale, NULL.
- Вычисленная цена: 100, 90, NULL; сравнение с NULL даёт NULL.
- WHERE: `= NULL` не пропускает строки, `IS NULL` находит id 3,
  `!= 0` — id 2, добавление `OR … IS NULL` — id 2 и 3.
- Логические исключения из неверного обобщения «всё с NULL даёт NULL»:
  `0 AND NULL = 0`, `1 OR NULL = 1`; `isNull(NULL) = 1`.
- count(), count(discount), sum(discount), avg(discount):
  смешанный набор — 3, 2, 10, 5; полностью NULL — 1, 0, NULL, NULL;
  пустой Nullable-набор — 0, 0, NULL, NULL.
- Пустой обычный UInt8: 0, 0, 0, nan при
  `aggregate_functions_null_for_empty=0`.
- Среднее с подставленным нулём — 3.3333333333333335, результат допущения.
- ifNull не меняет сохранённую скидку; coalesce сохраняет пустую строку;
  nullIf(label, '') позволяет нормализовать пустую подпись.
- VALUES со строгой обработкой NULL: ошибка 53 TYPE_MISMATCH;
  разрешённая подстановка использует DEFAULT столбца.
- INSERT SELECT: другой переключатель `insert_null_as_default`, строгая
  обработка даёт ошибку 349 CANNOT_INSERT_NULL_IN_ORDINARY_COLUMN.
- JSONEachRow с отсутствующим city: при
  `input_format_defaults_for_omitted_fields=0` пустая строка, при 1 —
  «не указан». Это не опыт с явным JSON null.
- Проверены ответы самопроверки и самостоятельной задачи.

## Вычитка A–E

A. У каждого содержательного раздела есть таблица, схема или реальный кадр.
Две схемы показывают чтение маски и преобразование строк при WHERE.
Восемь кадров Play UI сняты отдельным процессом Chromium с отдельными контекстами.
Это исходные кадры 2×; уменьшенные копии использовались только для просмотра.

B. Линия: смысл отсутствия → представление → defaults → ввод → выражения →
агрегаты → обоснованная замена. Побочная проверка форматов раскрывается отдельно,
но сами ограничения указаны в основном тексте. Добавлены переходы между этапами.

C. По review.py: первый черновик переработки — среднее 11.4 слова,
2 предложения длиннее 25 слов; после правок — 10.6 слова, 0 длиннее 25.
Для сравнения исходная глава: 10.4 слова, 1 длиннее 25.
Размер предложений не является самостоятельной оценкой качества объяснения.

D. Убраны «NULL заразен», «Nullable стоит денег», несколько искусственных
противопоставлений. Содержательные различия 0 / NULL сохранены.

E. Проверены запросы и ошибки запуском, настройки указаны явно.
Утверждения о производительности без воспроизводимого опыта исключены.

## Ограничения

Выводы относятся к указанной версии и способам вставки.
Стоимость Nullable не измеряется. Проверка не охватывает все форматы загрузки,
настройки профилей или агрегатные комбинаторы. Это сознательные границы главы,
а не заблокированные обязательные опыты.
